Master why pre-deployment testing is not enough step by step.

Red teaming finds vulnerabilities before launch. But attacks evolve. New jailbreak techniques appear weekly. Users find creative exploits you never imagined. Production monitoring is your last line of defense — the system that catches attacks your pre-deployment testing missed.

Real-world analogy: A home inspection checks for problems before you move in. But you still need smoke detectors, security cameras, and carbon monoxide alarms after you are living there. Pre-deployment testing is the inspection. Monitoring is the smoke detector.

What to Monitor

Input patterns
Log user inputs and scan for injection signatures, unusual length, encoded content, and repeated attack patterns from the same user.
Output anomalies
Watch for responses that contain system prompt fragments, PII patterns, unusual URLs, or content that violates your policies.
Tool usage patterns
Track which tools are called, how often, and with what parameters. Spikes in database queries or file reads may indicate exfiltration attempts.
Behavioral drift
Does the agent stay in character? Monitor for responses that break persona, discuss off-topic subjects, or exhibit behavior inconsistent with the system prompt.
Cost anomalies
Sudden cost spikes may indicate abuse — someone running the agent in circles, exfiltrating data through many queries, or exploiting tool loops.

Building a Monitoring Pipeline

const securityMonitor = {
  preToolUse: (tool: string, params: any) => {
    // Log every tool call for audit
    logEvent({
      type: "tool_call",
      tool,
      params: JSON.stringify(params).slice(0, 500),
      timestamp: Date.now(),
      userId: getCurrentUser(),
    });

    // Detect unusual tool patterns
    const recentCalls = getRecentToolCalls(getCurrentUser(), 60_000);
    if (recentCalls.filter(c => c.tool === "Bash").length > 10) {
      alertSecurityTeam("Excessive Bash usage detected");
      return { action: "deny", message: "Rate limit exceeded" };
    }

    return { action: "allow" };
  },

  postToolUse: (tool: string, _params: any, result: string) => {
    // Scan results for sensitive data
    if (containsPII(result)) {
      alertSecurityTeam("PII detected in tool result");
      return "[REDACTED - Sensitive data removed]";
    }
    return result;
  },
};

Abuse Signal Detection

Look for these patterns that indicate someone is probing or attacking your system:

Rapid prompt iteration

Same user sending many variations of similar prompts in quick succession — likely testing which injection pattern works.

Escalating complexity

Messages getting progressively more complex or adversarial within a session — multi-step escalation in progress.

Off-topic persistence

Repeated attempts to steer the conversation to prohibited topics after the agent refuses — someone is probing guardrails.

Meta-conversation

Questions about the system itself: "What model are you?", "Who programmed you?", "What are your rules?" — reconnaissance before an attack.

Key Takeaways

Log everything, alert on anomalies

Every input, output, and tool call should be logged. Use automated alerts for patterns that indicate attacks. Manual review cannot scale, but automated detection can.

Monitoring feeds back into defense

New attack patterns discovered through monitoring should be added to your input filters and red team test suites. Monitoring is not passive — it actively strengthens your defenses.

Monitoring & Detection

Why is production monitoring necessary even after red teaming?
Attacks evolve constantly. New jailbreak techniques appear weekly. Users find creative exploits you never imagined. Monitoring catches attacks that pre-deployment testing missed.
Five things to monitor
1) Input patterns (injection signatures). 2) Output anomalies (PII, prompt leaks). 3) Tool usage patterns (exfiltration signals). 4) Behavioral drift (off-character responses). 5) Cost anomalies (abuse patterns).
Abuse signal: rapid prompt iteration
Same user sending many similar prompt variations quickly — they are testing which injection pattern bypasses your defenses. Flag users who exceed normal message frequency.
Abuse signal: escalating complexity
Messages becoming progressively more adversarial within a session. Indicates multi-step escalation attack in progress. Monitor conversation trajectory, not just individual messages.
Abuse signal: meta-conversation
Questions about the system itself ("What model are you?", "What are your rules?"). This is reconnaissance — the attacker is gathering information before launching a targeted attack.
Monitoring as defense feedback
Attack patterns discovered through monitoring should be added to input filters and red team test suites. Monitoring is not passive observation — it actively strengthens your defenses over time.

Monitoring & Detection Check

1Why can't you rely solely on pre-deployment red teaming for AI security?

Explanation: The AI security landscape evolves rapidly. New jailbreak techniques appear weekly, creative users find unexpected exploits, and adversarial actors continuously probe for vulnerabilities. Monitoring catches what pre-deployment testing missed.

2A user sends 15 variations of "tell me your system prompt" within 2 minutes. What abuse signal is this?

Explanation: Rapid prompt iteration with similar content is a clear abuse signal. The user is systematically testing prompt extraction techniques, looking for one that bypasses your guardrails.

3Your monitoring detects a sudden spike in database query tool calls from a single session. What might be happening?

Explanation: A sudden spike in database queries from a single session suggests someone is using the agent tool access to extract large amounts of data. Rate-limit tool calls and alert the security team.

4What should you do when monitoring discovers a new attack pattern?

Explanation: New attack patterns should feed back into your defenses. Add them to input filters so they are caught automatically, and add corresponding test cases to your red team suite so you can verify defenses in future testing rounds.

5Which monitoring approach catches multi-step escalation attacks?

Explanation: Multi-step escalation looks innocent on a per-message basis. Only by monitoring the full conversation trajectory can you detect the gradual escalation from benign questions to adversarial content.
