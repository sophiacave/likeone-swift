System Prompt Architecture

Every Claude interaction has three layers of instructions. Understanding how they interact is critical for the CCA exam.

LAYER 1: SYSTEM PROMPT (set by developer)
  Purpose: Define the agent's role, capabilities, and boundaries.
  Visibility: Hidden from end users.
  Priority: High — Claude follows system prompt over user messages.

LAYER 2: CONTEXT (loaded dynamically)
  Purpose: Ground the agent in relevant knowledge.
  Sources: CLAUDE.md, RAG results, tool output, conversation history.
  Priority: Medium — informs responses but doesn't override system.

LAYER 3: USER MESSAGE (from the human)
  Purpose: The actual task or question.
  Priority: Lowest for behavioral rules, highest for task direction.

INTERACTION:
  System: "You are a code reviewer. Only discuss code."
  User: "Write me a poem about sunsets."
  Result: Claude declines — system prompt overrides user request.

  System: "You help with Python development."
  Context: "This project uses FastAPI and PostgreSQL."
  User: "Add an endpoint for user profiles."
  Result: Claude creates a FastAPI endpoint with PostgreSQL.

Writing Effective System Prompts

The Five Components

1. ROLE DEFINITION
   "You are a senior Python developer specializing in
    backend API development."
   → Sets expertise level and domain.

2. BEHAVIORAL RULES
   "Always write type hints. Always include docstrings.
    Never use global variables."
   → Specific, testable constraints.

3. OUTPUT FORMAT
   "Respond with code blocks. Include file paths as comments.
    Explain changes in 1-2 sentences, not paragraphs."
   → Controls how responses look.

4. BOUNDARIES
   "Only help with Python and SQL. Decline requests about
    frontend development or DevOps."
   → Defines what the agent will and won't do.

5. CONTEXT INSTRUCTIONS
   "When given a codebase question, search for relevant files
    before answering. Never guess at file contents."
   → How to use available tools and information.

Good vs Bad System Prompts

BAD: Too vague
  "Be a helpful assistant."
  → Provides no specific guidance. Claude's default behavior.

BAD: Too long (2000+ words)
  [Entire company handbook pasted as system prompt]
  → Burns context window. Claude loses focus on key rules.
  → Move detailed content to CLAUDE.md or RAG.

BAD: Contradictory
  "Be concise" + "Explain your reasoning in detail"
  → Claude can't satisfy both. Pick one.

BAD: Negative-only
  "Don't use semicolons. Don't add comments. Don't use any."
  → Tells Claude what NOT to do but not what TO do.
  → Add positive instructions: "Use newlines instead of semicolons."

GOOD: Specific, positive, concise
  "You are a TypeScript backend engineer.
   Write all code in strict TypeScript with Zod validation.
   Use Express.js patterns from this codebase.
   Keep responses under 100 lines. Explain non-obvious decisions
   in a single-line comment."
  → Role + rules + format + boundaries in 5 lines.

Identity Design for Agents

When building a user-facing AI product, the system prompt defines the agent's personality, expertise, and boundaries.

Identity Framework

DIMENSION 1: EXPERTISE LEVEL
  Options: Beginner-friendly | Peer-level | Expert
  Impact: Vocabulary, assumption level, explanation depth

  Beginner: "Explain each step. Define technical terms.
             Use analogies when helpful."
  Peer:     "Assume familiarity with standard patterns.
             Focus on the non-obvious aspects."
  Expert:   "Skip basics. Focus on edge cases, performance,
             and architectural trade-offs."

DIMENSION 2: COMMUNICATION STYLE
  Options: Formal | Conversational | Terse
  Impact: Sentence structure, tone, emoji usage

  Formal:       "Provide structured analysis with citations."
  Conversational: "Explain like you're talking to a colleague."
  Terse:        "Minimal words. Code over explanation. No filler."

DIMENSION 3: PROACTIVITY
  Options: Reactive | Suggestive | Proactive
  Impact: Whether the agent volunteers additional information

  Reactive:   Only answer what's asked.
  Suggestive: Answer + suggest related improvements.
  Proactive:  Answer + identify issues + propose fixes.

DIMENSION 4: AUTONOMY
  Options: Confirmatory | Semi-autonomous | Fully autonomous
  Impact: How much the agent does without asking

  Confirmatory:    "Propose changes. Ask before applying."
  Semi-autonomous: "Apply safe changes. Ask for risky ones."
  Fully autonomous: "Execute the best approach. Report results."
Exam tip: When designing an agent identity, explicitly state the level for each dimension. "Expert, terse, proactive, semi-autonomous" is a complete identity specification in 4 words.

Prompt Layering in Practice

How Layers Combine

SYSTEM PROMPT:
  "You are a security auditor for Python web applications.
   Focus on OWASP Top 10 vulnerabilities.
   Output findings in severity-ranked format."

CLAUDE.md:
  "This project uses Django 5.0 with PostgreSQL.
   Auth is handled by django-allauth.
   All user input goes through Django forms."

USER MESSAGE:
  "Review the login view in accounts/views.py"

CLAUDE'S EFFECTIVE CONTEXT:
  Role: Security auditor (from system prompt)
  Focus: OWASP Top 10 (from system prompt)
  Format: Severity-ranked (from system prompt)
  Framework knowledge: Django 5.0 (from CLAUDE.md)
  Auth context: django-allauth (from CLAUDE.md)
  Input handling: Django forms (from CLAUDE.md)
  Task: Review accounts/views.py (from user)

  → Claude reads the file, evaluates against OWASP Top 10,
     understands Django-specific patterns, and outputs findings
     ranked by severity. All three layers contributed.

Layer Conflicts

CONFLICT 1: System vs CLAUDE.md
  System: "Write all code in JavaScript"
  CLAUDE.md: "This project uses TypeScript"
  → CLAUDE.md wins for project context.
     System prompt sets general behavior.
     CLAUDE.md overrides for specific project.

CONFLICT 2: System vs User
  System: "Never execute destructive commands"
  User: "Run rm -rf /tmp/old-builds"
  → System wins. Safety rules override user requests.
     This is by design — users cannot bypass safety.

CONFLICT 3: CLAUDE.md vs User
  CLAUDE.md: "Always run tests before committing"
  User: "Commit without tests, I'll fix later"
  → User wins for direct instructions (it's their project).
     But Claude may warn about violating CLAUDE.md guidance.

Exam Scenario Practice

Scenario: Customer Support Bot

QUESTION:
  Design a system prompt for a customer support bot that:
  - Handles software product support
  - Can access knowledge base and ticket system
  - Should escalate billing issues to humans
  - Must never share internal pricing logic

STRONG ANSWER:
  "You are a support agent for [Product Name].

   CAPABILITIES:
   - Search the knowledge base for answers
   - Look up customer accounts and ticket history
   - Create and update support tickets
   - Provide step-by-step troubleshooting

   BOUNDARIES:
   - Billing questions: create a ticket tagged 'billing-escalation'
     and inform the customer a specialist will follow up.
     Do NOT attempt to resolve billing issues.
   - Internal pricing, margins, or cost structures: decline with
     'I don't have access to that information.'
   - Feature requests: log as ticket tagged 'feature-request'
     and thank the customer.

   STYLE:
   - Professional and empathetic
   - Acknowledge frustration before troubleshooting
   - Use the customer's name
   - Keep responses under 150 words unless step-by-step guide

   ESCALATION TRIGGERS:
   - Customer explicitly asks for a human
   - Issue unresolved after 3 exchanges
   - Legal or compliance mentions
   - Account security concerns"

WHY THIS WORKS:
  - Clear role and capabilities
  - Explicit boundaries (billing, pricing, features)
  - Style guidance (empathetic, concise)
  - Escalation rules (specific triggers, not vague)

Scenario: Code Review Agent

QUESTION:
  Design a system prompt for an automated code review agent
  that posts PR comments. It should be helpful but not annoying.

STRONG ANSWER:
  "You are a code review assistant.

   REVIEW FOCUS (in priority order):
   1. Bugs — logic errors, null pointer risks, race conditions
   2. Security — injection, auth bypass, data exposure
   3. Performance — N+1 queries, unnecessary allocations, O(n^2)
   4. Maintainability — naming, complexity, missing tests

   RULES:
   - Only comment on changed lines (not entire file)
   - Maximum 5 comments per PR (prioritize by severity)
   - Never comment on style/formatting (linters handle that)
   - Praise good patterns: 'Nice use of [pattern]' (max 1 per PR)
   - If no issues found, post: 'Looks good! No concerns.'

   FORMAT:
   Each comment:
     **[severity]** Brief description
     ```suggestion
     // improved code
     ```
     Why: one-sentence explanation

   NEVER:
   - Rewrite entire functions (suggest, don't rewrite)
   - Comment on variable names unless truly confusing
   - Block PRs for minor issues (use 'nit:' prefix)"

KEY DESIGN CHOICES:
  - Comment cap (5) prevents review fatigue
  - Priority order ensures important issues surface first
  - Explicit praise rule prevents an all-negative experience
  - "Looks good" default reduces noise for clean PRs

Key Takeaways for the Exam

  1. System prompts define role, rules, format, and boundaries. All four components matter.
  2. Three layers: system → context → user. System sets behavior, context grounds knowledge, user directs tasks.
  3. Specific beats vague. "Max 5 comments per PR" beats "don't be too verbose."
  4. Identity = expertise + style + proactivity + autonomy. Specify all four dimensions.
  5. Boundaries must be explicit. What the agent won't do is as important as what it will.
  6. Short system prompts > long ones. Move detailed knowledge to CLAUDE.md or RAG.
CCA exam weight: System prompts appear in Domain 3 (Configuration) and Domain 2 (Architecture). Expect 2-3 questions testing prompt design, layer interaction, and identity specification.
