Exam Format

CCA FOUNDATIONS EXAM:
  Questions:    60
  Time:         90 minutes
  Passing:      720/1000 (approximately 72%)
  Format:       Multiple choice + scenario-based
  Cost:         $99
  Retake:       14-day wait, $99 per attempt
  Delivery:     Online, proctored

DOMAIN WEIGHTS:
  Domain 1 — Tool Use:              25%  (~15 questions)
  Domain 2 — Agentic Architecture:  25%  (~15 questions)
  Domain 3 — Configuration:         20%  (~12 questions)
  Domain 4 — Deployment:            15%  (~9 questions)
  Domain 5 — Security:              15%  (~9 questions)

QUESTION TYPES:
  Type A — Single best answer (most common):
    "Which is the MOST appropriate approach?"
    → One clearly best answer. Others are partially correct.

  Type B — Scenario analysis:
    "Given this requirement, design the solution."
    → Longer question. Tests applied knowledge.
    → Usually worth more points.

  Type C — Anti-pattern identification:
    "What is WRONG with this design?"
    → Tests negative knowledge (what NOT to do).

Time Management

BUDGET: 90 seconds per question average.

STRATEGY:
  FIRST PASS (50 minutes):
    - Answer all questions you're confident about
    - Skip hard questions (mark for review)
    - Target: answer 40-45 questions
    - Average: 75 seconds per answered question

  SECOND PASS (30 minutes):
    - Return to marked questions
    - Eliminate wrong answers, then choose
    - Target: answer remaining 15-20 questions
    - Average: 100 seconds per remaining question

  REVIEW (10 minutes):
    - Review any answers you're uncertain about
    - Check for misread questions
    - Don't change answers unless you're sure

TIME TRAPS:
  ✗ Spending 5 minutes on one question
    → Mark it, move on. Come back later.
  ✗ Second-guessing every answer
    → First instinct is usually correct.
  ✗ Reading every option before reading the question
    → Read question first. Form your answer. Then check options.

PACING CHECK:
  At 30 minutes: should have 20 questions answered
  At 60 minutes: should have 40 questions answered
  At 80 minutes: all questions answered, reviewing

Answer Elimination Strategy

STEP 1: READ THE QUESTION STEM
  Identify what's being asked: BEST, WRONG, FIRST, MOST.
  "What should you do FIRST" ≠ "What should you do"
  "Which is WRONG" = find the bad answer.

STEP 2: FORM YOUR ANSWER BEFORE READING OPTIONS
  If you know the answer, you'll recognize it in the options.
  This prevents being tricked by plausible wrong answers.

STEP 3: ELIMINATE OBVIOUSLY WRONG OPTIONS
  Usually 1-2 options are clearly wrong.
  Eliminating narrows your odds from 25% to 50%.

COMMON WRONG ANSWER PATTERNS:

  ABSOLUTE ANSWERS:
    "Always use multi-agent" → Wrong (depends on use case)
    "Never use bash in CI" → Wrong (restricted bash is fine)
    Absolute words (always, never, all, none) are usually wrong.

  TOO VAGUE:
    "Use best practices" → Not specific enough to be correct.
    "Ensure security" → How? This says nothing actionable.

  WRONG SCOPE:
    Question asks about CI, answer talks about local development.
    Question asks about security, answer talks about performance.

  PARTIALLY CORRECT:
    Answer is good advice but doesn't address the MAIN issue.
    "Add logging" is always good but may not be the BEST answer.

Domain-Specific Tips

Domain 1 — Tool Use (25%)

MUST KNOW:
  - Three MCP primitives: tools, resources, prompts
  - Tool descriptions determine when Claude calls them
  - stdio vs HTTP/SSE transport selection
  - Input validation belongs on the server, not the model
  - One server per domain (don't build god-servers)
  - Confirmation barriers for destructive operations

COMMON TRAPS:
  - Confusing tools (model-controlled) with resources (app-controlled)
  - Designing tools with too many required parameters
  - Forgetting error response design

Domain 2 — Architecture (25%)

MUST KNOW:
  - Single agent vs multi-agent decision framework
  - Four topologies: supervisor, pipeline, debate, swarm
  - Three persistence tiers: ephemeral, file-backed, database
  - State handoff: write during session, not just at end
  - Context window is finite — design for it
  - Extended thinking for complex reasoning tasks

COMMON TRAPS:
  - Choosing multi-agent when single-agent suffices
  - Relying on conversation history for cross-session state
  - Ignoring context window limits in design

Domain 3 — Configuration (20%)

MUST KNOW:
  - Hierarchy: enterprise > project > user > defaults
  - CLAUDE.md for shared project rules, ~/.claude/rules for personal
  - Subdirectory CLAUDE.md adds to (doesn't replace) root
  - Custom commands: .md files in .claude/commands/
  - Hooks: pre-tool (block), post-tool (log/lint)
  - Permission modes: allowlist, prompt, trust

COMMON TRAPS:
  - Putting personal preferences in project CLAUDE.md
  - Not understanding how subdirectory configs cascade
  - Choosing wrong permission mode for the context

Domain 4 — Deployment (15%)

MUST KNOW:
  - Headless mode: claude -p with --allowedTools
  - Retry: exponential backoff, honor Retry-After
  - Fallback: degraded functionality > complete failure
  - Circuit breaker: stop calling dead services
  - Guardrails: max tool calls, output validation, scope limits
  - Monitoring: error rate, latency, cost, quality

COMMON TRAPS:
  - Retrying 400 errors (fix the request instead)
  - No fallback for external dependencies
  - Forgetting cost management in scaling scenarios

Domain 5 — Security (15%)

MUST KNOW:
  - Server validates, not the model
  - Parameterized queries always (prevent SQL injection)
  - Filter sensitive fields before returning to model
  - Least privilege for database access
  - Rate limit destructive operations
  - Audit trail for compliance
  - Template-based output for sensitive operations

COMMON TRAPS:
  - Relying on system prompt for security ("tell Claude not to...")
  - Returning full database records with PII
  - No audit trail in compliance scenarios
